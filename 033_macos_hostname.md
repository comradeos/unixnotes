# macOS: имя хоста в Terminal изменилось с macbook на pc-lab-markov

## Проблема

Раньше приглашение Terminal содержало имя `macbook`, затем стало выглядеть так:

```text
io@pc-lab-markov ~ %
```

В приглашении `io` — имя пользователя, а `pc-lab-markov` — короткое имя хоста.

## Диагностика

Проверить текущее имя хоста и сохранённые настройки macOS:

```bash
hostname
scutil --get HostName
scutil --get LocalHostName
scutil --get ComputerName
```

Во время диагностики получены следующие значения:

| Команда | Результат |
| --- | --- |
| `hostname` | `pc-lab-markov.elvatech.local` |
| `scutil --get HostName` | `HostName: not set` |
| `scutil --get LocalHostName` | `macbook` |
| `scutil --get ComputerName` | `MacBook` |

Обратное DNS-разрешение текущего IP-адреса также вернуло
`pc-lab-markov.elvatech.local`.

## Причина

В macOS используются несколько отдельных имён:

- `ComputerName` — отображаемое имя компьютера, например `MacBook`.
- `LocalHostName` — имя Bonjour, например `macbook`, доступное в локальной сети
  как `macbook.local`.
- `HostName` — явно заданное системное имя хоста.

Если `HostName` не задан, macOS может определять имя хоста по данным сети,
в том числе через обратный DNS-запрос для текущего IP-адреса.

В данном случае имя компьютера и имя Bonjour сохранились, а системное имя
совпало с результатом обратного DNS-запроса. Это указывает на сетевой источник
имени `pc-lab-markov`. Вероятное объяснение — в DNS осталась запись другого
компьютера, которому раньше принадлежал этот IP-адрес. История DNS-записи
не проверялась, поэтому эта причина остаётся предположением.

## Решение

Явно закрепить системное имя хоста:

```bash
sudo scutil --set HostName "macbook"
```

Команда требует пароль администратора. Проверить результат:

```bash
scutil --get HostName
hostname
```

Ожидаемый результат обеих команд:

```text
macbook
```

Открыть новую вкладку или окно Terminal. При прежних настройках приглашения
оно должно выглядеть так:

```text
io@macbook ~ %
```

Менять `ComputerName` и `LocalHostName` в этом случае не требуется:
они уже имеют нужные значения. Перезагрузка Mac не нужна.

Установка `HostName` задаёт имя на самом Mac; DNS-запись в сети она
не исправляет. Если нужно исправить и обратное DNS-разрешение, следует
обновить соответствующую PTR-запись на DNS-сервере или роутере.
