# UART через USB в Linux

[Общая схема подключения и параметры UART](README.md).

## 1. Установить утилиты

Основной вариант — `picocom`. `screen` можно установить как альтернативу.
Выполни команды только для своего дистрибутива.

### Debian / Ubuntu / Raspberry Pi OS

```bash
sudo apt update
sudo apt install picocom screen
```

### Fedora

```bash
sudo dnf install picocom screen
```

### Arch Linux

```bash
sudo pacman -Syu picocom screen
```

Проверить установку:

```bash
command -v picocom
picocom --help
```

Если работаешь от `root`, команды установки выполняются без `sudo`.
Ошибка `picocom: command not found` означает, что команда не найдена:
проверь установку и `PATH`. Сам по себе `sudo` утилиту не устанавливает.

## 2. Найти порт

Подключи адаптер и посмотри сообщения ядра:

```bash
sudo dmesg | tail -n 50
```

Для наблюдения в реальном времени запусти `sudo dmesg -w`, затем подключи адаптер.
Выйти из просмотра — `Ctrl+C`.

Найти устройства, в том числе при работе из zsh:

```bash
find /dev -maxdepth 1 \( -name 'ttyUSB*' -o -name 'ttyACM*' \) -print
```

Обычно USB–UART-адаптер получает `/dev/ttyUSB0`, а USB CDC ACM — `/dev/ttyACM0`.
Число может отличаться. Сравни список до и после подключения.

Если доступны постоянные ссылки, их удобнее использовать при нескольких адаптерах:

```bash
ls -l /dev/serial/by-id/
```

Полный путь `/dev/serial/by-id/...` можно передать picocom вместо `/dev/ttyUSB0`.
Каталог `by-id` существует не для всех устройств.

## 3. Настроить доступ без sudo

Сначала проверь владельца и группу реального порта:

```bash
ls -l /dev/ttyUSB0
id -nG
```

В Debian / Ubuntu порт обычно принадлежит группе `dialout`:

```bash
sudo usermod -aG dialout "$USER"
```

В Arch Linux это часто группа `uucp`:

```bash
sudo usermod -aG uucp "$USER"
```

Выбери группу по выводу `ls -l`; обе команды подряд выполнять не нужно.
После изменения выйди из пользовательского сеанса и войди заново
либо переподключись по SSH. Проверь членство командой `id -nG`.
Для разовой проверки до настройки прав можно запустить picocom с `sudo`.

## 4. Подключиться через picocom

Пример для `/dev/ttyUSB0` с параметрами 115200, 8N1 и без flow control:

```bash
picocom -b 115200 -d 8 -p 1 -y n -f n /dev/ttyUSB0
```

Замени путь и скорость на свои. Краткая форма с теми же стандартными
параметрами 8N1 и отключённым flow control:

```bash
picocom -b 115200 /dev/ttyUSB0
```

После открытия нажми `Enter`. Пустой экран возможен, пока устройство ничего
не передаёт. Для загрузочного лога перезапусти целевую плату.

Сочетания нажимаются последовательно: сначала `Ctrl+A`, отпустить, затем второе.

| Действие | Клавиши |
| --- | --- |
| Выйти | `Ctrl+A`, затем `Ctrl+X` |
| Справка | `Ctrl+A`, затем `Ctrl+H` |
| Показать параметры | `Ctrl+A`, затем `Ctrl+V` |
| Включить / выключить локальное эхо | `Ctrl+A`, затем `Ctrl+C` |

Обычный `Ctrl+C` передаётся подключённому устройству. Если ввод не виден,
устройство может не возвращать эхо: включи локальное эхо. Если символы
дублируются — выключи его.

### Сохранить лог

```bash
picocom -b 115200 -g uart-linux.log /dev/ttyUSB0
```

Файл создаётся в текущем каталоге; существующий дополняется. По умолчанию
записываются принятые данные, а при локальном эхо — также отправляемые.

## 5. Альтернатива: screen

Сначала закрой picocom, затем открой тот же порт:

```bash
screen /dev/ttyUSB0 115200
```

Выход: `Ctrl+A`, затем строчная `k`, затем `y` для подтверждения.
`Ctrl+A`, затем `d` только отсоединяет окно: сессия остаётся и держит порт.
Вернуться к ней можно через `screen -ls` и `screen -r ИДЕНТИФИКАТОР`.

## Если не работает

| Симптом | Что проверить |
| --- | --- |
| `Permission denied` | Группу порта, `id -nG` и повторный вход после `usermod` |
| `No such file or directory` | Найди порт заново: номер мог измениться |
| `Device or resource busy`, ошибка блокировки | Закрой другие serial-терминалы, Serial Monitor IDE и оставшиеся сессии screen |
| Порт не появляется | Кабель с передачей данных, другой USB-разъём, сообщения `dmesg`; `lsusb` из пакета `usbutils` поможет определить адаптер |
| Нечитаемые символы | Скорость, 8N1 и уровни сигналов |
| Нет вывода / реакции | Питание платы, общий GND, TX ↔ RX, включённую UART-консоль, flow control и окончание строки |

Найти процесс, открывший порт (если `fuser` установлен, обычно пакет `psmisc`):

```bash
sudo fuser -v /dev/ttyUSB0
```

Если устройство требует CR+LF при нажатии Enter, закрой сессию и попробуй:

```bash
picocom -b 115200 --omap crcrlf /dev/ttyUSB0
```
